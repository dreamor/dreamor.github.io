🔗 RAG 增强阶段 (Augment)

如何把检索结果变成 LLM 能"看懂"的提示？

🎯 核心问题：检索到的文档如何变成 LLM 的"输入"

💡 类比：给律师提供案件档案

假设你需要代理一起复杂的商业诉讼案件：

❌ 单纯检索的问题

你递给律师一箱20斤的案件材料，说："帮我打这场官司。"

律师需要自己理解、筛选、提炼有用的信息...

✅ RAG 增强的好处

你递给律师一份整理好的"摘要+关键证据清单+辩论要点"。

律师直接基于整理好的材料起草辩护词，效率高、遗漏少。

RAG 的 Augment 阶段就是做这件事：把检索到的文档碎片，组装成一个结构清晰、信息完备的 Prompt，让 LLM 能够直接"看懂"并生成正确答案。

🤔 增强 vs 改写：RAG 到底在做什么？

一个常见的误解：RAG 增强是不是就是"系统改写用户的 Prompt"？

📐 更准确的说法：增强/补充，而非改写

❌ 改写 (Rewrite)
  • 修改用户的原始问题
  • 用同义词、改述等方式
  • 不增加新信息
  • 如："啥是ML" → "什么是机器学习"
✅ 增强 (Augment)
  • 保留原始问题，添加额外信息
  • 注入外部检索到的知识
  • 增加用户没提供的信息
  • 如：添加检索到的文档内容

🎬 增强过程可视化

原始 Prompt:
"什么是机器学习？"
        ↓
==================== RAG 增强 ====================
        ↓
增强后 Prompt:
"""
【系统指令】
你是一个有帮助的 AI 助手，基于提供的参考资料回答问题。

【参考资料】
1. 机器学习是人工智能的一个分支...（检索到的文档1）
2. 机器学习算法可以从数据中学习...（检索到的文档2）
3. 常见的机器学习方法包括监督学习、无监督学习...（检索到的文档3）

【用户问题】
什么是机器学习？

【回答要求】
请基于参考资料回答，不要编造信息。如果参考资料中没有相关信息，请如实告知。
"""
💡 RAG 增强 = 原始 Prompt + 检索知识 + 格式化指令

不是"改写"用户的问题，而是"补充"回答问题所需的外部信息。

让模型能基于事实回答，而不是依赖训练数据中可能过时或错误的知识。

📋 RAG 增强的常见组成部分

系统指令

设定角色、任务目标、回答风格

检索上下文

从知识库检索的相关文档片段

用户问题

保留原始问题，不做修改

回答约束

要求基于上下文回答、禁止编造等

⚠️ 常见误区

误区正确理解
RAG 会改写用户的问题 保留原始问题，只是添加上下文
检索到的内容直接作为回答 检索内容作为参考，LLM 基于此生成回答
RAG 能解决所有幻觉问题 减少幻觉，但检索错误或上下文不足仍可能导致错误

🔄 Reranker 重排序机制

阶段 1：向量检索结果

  • 1MiniMind 模型架构0.92
  • 2注意力机制详解0.89

  • 3位置编码方法0.91
  • 4注意力机制详解0.87

💡 为什么需要 Reranker？

向量检索基于语义相似度，可能返回与查询词相似但上下文不相关的文档。Reranker 使用 Cross-Encoder 同时编码 Query 和 Document，能够更准确地判断两者的相关性。

💻 Reranker 代码示例

Python - Reranker 实现
from sentence_transformers import CrossEncoder

# 1. 初检索返回 Top-20 结果
initial_results = vector_db.search(query_embedding, top_k=20)

# 2. Reranker 重新评分
reranker = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
query_doc_pairs = [(query, doc) for doc in initial_results]
scores = reranker.predict(query_doc_pairs)

# 3. 按新分数排序
ranked_indices = scores.argsort()[::-1][:5]
final_results = [initial_results[i] for i in ranked_indices]
向量检索

fast, 支持百万级 doc 检索，但精度有限

Cross-Encoder

精度高，但计算量大，适合小规模重排
