👍 DPO 偏好优化

让模型学习"什么是更好的答案"

🎯 SFT、DPO、GRPO 三者对比

三者都是在预训练模型基础上微调，但学习方式和数据标签不同：

SFTDPOGRPO
本质 监督学习 偏好学习（离线） 偏好学习（在线）
数据标签 标准答案 偏好排序（哪个更好） Reward 评分
数据来源 人工标注 人类标注/AI 反馈 模型自己生成
训练阶段 SFT 之后 SFT 之后 SFT 之后
典型应用 基础能力 对齐人类偏好 数学/代码推理
💡 通俗类比

SFT = 老师出题，学生抄答案，背答案

DPO = 老师展示两份答案，学生判断哪个更好，反复练习好答案

GRPO = 学生自己写多份答案，自己批改认为最好的，反复练习最好的

🎯 为什么需要 DPO？

SFT 后模型已经能回答问题，但答案可能有高下之分：

✗ 差答案

用户：今天天气怎么样？

答：还行。

问题：太简短，没帮助

✓ 好答案

用户：今天天气怎么样？

答：今天天气很好，适合户外活动。预计最高温度 28℃，晴转多云。

优点：详细、有用

💡 DPO 的核心思想

不需要人工标注"正确答案是多少"，只需要比较两个答案，告诉模型哪个更好

📋 DPO 数据格式

每条训练数据包含：问题 + 好答案 + 差答案

{
  "prompt": "今天天气怎么样？",
  "chosen": "今天天气很好，适合户外活动...",   # ✓ 好答案
  "rejected": "还行。"                              # ✗ 差答案
}
字段含义作用
prompt 用户问题 输入给模型
chosen 人工标注的好答案 目标输出
rejected 人工标注的差答案 需要避免的输出

📐 DPO 损失函数与参数更新

1. 计算偏好概率
π(x)chosen vs π(x)rejected
→
2. 计算奖励差
r = logπchosen - logπrejected
→
3. 梯度更新
让 r 越来越大
L = -log(σ(r_chosen - r_rejected))

其中 r = log π(y)/π_ref(y) 是偏好奖励

📐 梯度更新详解

DPO 的梯度方向：增加选中答案的概率，降低拒绝答案的概率

如果 chosen 比 rejected 好

r_chosen - r_rejected > 0
Loss 低，梯度小
参数只需小幅调整

如果 chosen 比 rejected 差

r_chosen - r_rejected < 0
Loss 高，梯度大
参数大幅更新，提高 chosen 概率

直观理解：

# DPO 希望 selected 的 reward 减去 rejected 的 reward 越来越大
diff = log_prob(chosen) - log_prob(rejected)

# Loss 高 → 梯度大 → 更新参数让 chosen 概率↑，rejected 概率↓
loss = -log(sigmoid(diff))

# 梯度方向：增加选中答案概率，降低拒绝答案概率
grad = ∂Loss/∂θ = (reward_rejected - reward_chosen) × 更新方向

📐 DPO 梯度流向详解

DPO 的梯度同时作用在 chosen 和 rejected 上，但方向相反：

对 chosen 答案的梯度：

# log π(y|x) 的梯度 = 提高chosen路径的激活程度
∇θ log πθ(chosen)  →  增大选中答案的概率

对 rejected 答案的梯度：

# -∇θ log π(y|x) 的梯度 = 降低rejected路径的激活程度
-∇θ log πθ(rejected)  →  减小拒绝答案的概率

两者相加：总梯度 = 提高chosen + 降低rejected = 拉开两者差距

💡 DPO 为什么有效？

SFT 的问题

  • 只能学习"正确答案"
  • 无法区分"好的"和"差的"答案
  • 对同一个问题，只有一个标准答案

DPO 的优势

  • 通过比较学习"偏好"
  • 利用相对关系而非绝对标签
  • 信号更强：好 vs 差 的区别

🔄 DPO 训练流程

# DPO 训练步骤

# 1. 从 SFT 模型开始
policy_model = load_sft_model()
ref_model = load_sft_model()  # 参考模型（不更新）

# 2. 对于每条数据 (prompt, chosen, rejected)
for batch in dataloader:
    prompt = batch["prompt"]
    chosen = batch["chosen"]
    rejected = batch["rejected"]

    # 3. 计算当前模型和参考模型的 log 概率
    log_pi_chosen = model(prompt + chosen).log_prob()
    log_pi_rejected = model(prompt + rejected).log_prob()
    log_ref_chosen = ref_model(prompt + chosen).log_prob()
    log_ref_rejected = ref_model(prompt + rejected).log_prob()

    # 4. 计算偏好奖励 r = log(π/π_ref)
    r_chosen = log_pi_chosen - log_ref_chosen
    r_rejected = log_pi_rejected - log_ref_rejected

    # 5. 计算 DPO Loss
    diff = r_chosen - r_rejected
    loss = -log(sigmoid(diff))

    # 6. 反向传播更新参数（默认全部参数，或只用 LoRA）
    loss.backward()
    optimizer.step()
💡 为什么需要参考模型 π_ref？

防止模型更新后偏离原始 SFT 太远，避免灾难性遗忘。参考模型是训练开始前的模型快照。

🔍 KL 散度的直观理解

KL(π || π_ref) 衡量新模型 π 相对于参考模型 π_ref 的"偏离程度"：

KL ≈ 0

新模型和参考模型几乎一样

KL >> 0

新模型严重偏离参考模型（可能出问题了）

# KL 散度公式
KL(π || π_ref) = Σ π(y) × log(π(y) / π_ref(y))

# DPO 实际隐式地包含了 KL 约束
# 因为 r = log(π/π_ref)，reward 已经包含了与参考模型的比较

🔄 DPO vs GRPO：负样本的处理方式

DPO 和 GRPO 对"负样本"（差答案）的处理方式不同：

方面DPOGRPO
负样本来源 人工标注的 rejected 答案 模型自己生成的低分答案
负信号强度 固定，取决于标注质量 动态，取决于相对比较
分布偏移风险 较低（人类撰写） 较高（模型自己生成）

DPO 的优势：rejected 答案是人类写的，分布更合理
GRPO 的优势：可以生成无限多对比，scalability 更好

🔢 批量梯度更新机制

所有方法（SFT/DPO/GRPO）都采用批量梯度下降：

# 三种方法都是这个模式
for batch in dataset:           # 每次取一批数据
    loss = compute_loss(batch)        # 计算损失
    loss.backward()                   # 反向传播
    optimizer.step()                  # 更新参数
💡 使用 LoRA 时的区别

默认更新全部参数；用 LoRA 时只更新 A、B 矩阵：

  • 全参数微调：W, A, B 全部更新
  • LoRA 微调：只有 A 和 B 矩阵更新，原始 W 冻结

📝 总结

DPO = 比较学习，让模型知道"哪个答案更好"

🎯 DPO 关键点：

  • 数据形式：(问题, 好答案, 差答案) 三元组
  • 训练目标：最大化好答案 vs 差答案的概率差
  • 梯度方向：提高偏好答案概率，降低拒绝答案概率
  • 参考模型：防止灾难性遗忘
  • 训练稳定：不需要复杂的 RL 算法
