👨‍🏫 监督微调 (SFT)

如何让模型"听懂"人类的指令？

🎯 核心理解：SFT 本质上是监督训练

SFT 和预训练的训练机制完全一样，都是 Next Token Prediction + 交叉熵 loss，区别只是数据不同。

💡 类比

预训练 = 大量自学教材 → 做"完形填空" → 学会语言规律

SFT = 有老师批改的作业 → 给定问题，有标准答案 → 学会回答问题

预训练SFT
本质 自监督学习 监督学习（就是训练！）
Loss 计算 完全一样 = 交叉熵 (Next Token Prediction)
数据来源 互联网海量文本（无标签） 人工标注的指令-回答对
输入格式 连续文本段落 对话格式：[USER] 指令 [ASSISTANT] 回答
训练目标 学会语言规律 学会听懂指令并正确回答

🔑 关键洞察

代码层面，SFT 和预训练几乎一样：

# 预训练
loss = cross_entropy(logits[:, :-1], labels[:, 1:])

# SFT（监督微调）
loss = cross_entropy(logits, expected_response)

区别：预训练自己预测下一个词，SFT 的"正确答案"是人工标注的

📋 SFT 数据格式

SFT 使用特殊的对话格式，包含 user（用户）和 assistant（助手）的多轮对话：

User: 请问什么是人工智能？
[INST] 请问什么是人工智能？ [/INST]
人工智能是计算机科学的一个分支，致力于开发能够执行通常需要人类智能的任务的系统...
User: 它和机器学习有什么关系？
[INST] 它和机器学习有什么关系？ [/INST]
机器学习是人工智能的一个子领域，它使计算机能够从数据中学习并改进性能...

JSON 格式数据示例：

{
  "conversations": [
    {"role": "user", "content": "请问什么是人工智能？"},
    {"role": "assistant", "content": "人工智能是..."},
    {"role": "user", "content": "它和机器学习有什么关系？"},
    {"role": "assistant", "content": "机器学习是..."}
  ]
}

🎭 Label Masking（标签掩码）

SFT 训练时，只对 assistant 的回答部分计算 loss，user 的问题部分忽略：

输入序列（拼接后的 token）：

[BOS] 请问 什么是 人工 智能 ？ [INST] [/INST] 人工 智能 是 计算机 科学 的 ... [EOS]
灰色部分

Label = -100（忽略）

绿色部分

Label = 真实 token（计算 loss）

# 实现 label masking
labels = input_ids.clone()
labels[:user_end_pos] = -100  # user 部分忽略

# 交叉熵损失自动忽略 label=-100 的位置
loss = F.cross_entropy(logits.view(-1, vocab_size), labels.view(-1), ignore_index=-100)

SFT 本质上也是 Next Token Prediction，但：

  • 数据格式不同：对话格式 vs 纯文本
  • Label 不同：只对 assistant 回答部分计算 loss
  • 数据量不同：通常几万到几十万条对话
  • 训练目标不同：学会回答问题 vs 学会续写文本

📊 SFT 数据质量至关重要

SFT 的效果很大程度上取决于数据质量：

维度好数据差数据
格式 规范统一，符合模板 格式混乱，缺失字段
内容 答案准确，有帮助 答案错误，有害内容
多样性 覆盖各种任务类型 数据单一，重复多
长度 答案长度适中 过长或过短

🔬 SFT 与预训练的本质区别

表面上 SFT 和预训练都是 Next Token Prediction，但实际上有几个关键区别：

维度预训练SFT
数据来源 互联网海量文本（无标签） 人工标注的指令-回答对
正确答案 文本中"恰好是下一个词" 人工认为的"最好回答"
Label 计算位置 所有 token 都计算 loss 只计算 assistant 回答部分 loss
学习目标 学会续写文本的一般规律 学会遵循指令、回答问题
Prompt 影响 不考虑 prompt（纯文本续写） 学会理解 prompt 并响应
💡 关键洞察：为什么 label masking 很重要？

如果对 user 部分也计算 loss：

  • 模型会"记住"用户的问题（过拟合 user 输入）
  • 模型学到的是"用户怎么问，我就怎么答"，而不是真正理解任务
  • 不同用户的相同问题会学到相同的回答模式

只对 assistant 回答计算 loss，确保模型专注于学习"如何回答"，而不是"记住问题"

🧠 SFT 能学到什么？

预训练让模型学会语言规律，SFT 让模型学会"听话"：

❌ 预训练能做的

  • 续写故事、续写文章
  • 完成句子、补全代码
  • 语言翻译（隐式）
  • 问答（基于文中的信息）

✓ SFT 后能做的

  • 遵循明确指令（"请解释..."）
  • 多轮对话保持上下文
  • 角色扮演、风格控制
  • 工具调用、代码执行
💡 类比

预训练 = 大量阅读各学科书籍 → 学会语言本身

SFT = 通过"做题"学会应用 → 学会按要求回答

⚠️ 为什么 SFT 之后还需要 DPO/GRPO？

SFT 学到的是"标准答案"，但人类偏好远比"标准答案"复杂：

SFT 认为的好答案

巴黎是法国的首都，人口约220万...

标准、正确、但可能过于机械

人类真正喜欢的好答案

巴黎超棒的！不仅是浪漫之都，还有埃菲尔铁塔、卢浮宫...人口不多但超级有魅力！

生动、有感染力、符合人类偏好

💡 DPO/GRPO 的作用

SFT 学"标准答案"，DPO/GRPO 学"人类偏好"

DPO/GRPO 不会改变模型的基础能力，而是在 SFT 基础上进一步对齐人类的"品味"

📝 总结

SFT = 预训练模型 + 指令数据 → 微调 → 学会回答问题

🎯 SFT 关键点：

  • 数据格式：多轮对话，user/assistant 交替
  • Label Masking：只对 assistant 回答计算 loss
  • 数据量：通常 10K-100K 条对话
  • 数据质量：答案准确、格式规范、多样性足
  • 学习率：通常比预训练小 10-100 倍
