📚 RAG 检索阶段 (Retrieval)

大模型如何"找到"相关文档？

🎯 核心问题

在 RAG (Retrieval-Augmented Generation) 系统中，检索阶段是至关重要的一步：当用户提问时，如何从海量文档中找到最相关的那些？

💡 类比：图书馆搜索

想象你走进一个藏书百万册的图书馆，想找"如何学习 Python 编程"相关的书籍。

🏠 生活类比

传统的关键词搜索就像按照书名的字母顺序查找——慢且不准确。
而 向量检索 就像是有一位图书管理员，她读过所有书，理解每本书的内容，
能根据你的问题直接推荐最相关的几本。这就是 RAG 检索的核心思想！

RAG 检索 = 将文档和问题都转为向量 → 在向量空间中找"距离最近"的文档

🔬 RAG Embedding 模型详解

以下是 RAG 检索中 Embedding 模型的训练原理和实现方式：

1. 核心目标：语义匹配

RAG 的 Embedding 任务只有一个目标：把查询和文档映射到同一个向量空间，让语义相近的内容距离更近。

3. 训练方法：对比学习 (Contrastive Learning)

这是 RAG Embedding 和 LLM Embedding 最大的区别 — InfoNCE 损失函数：

Loss = -log( exp(sim(q, d⁺) / τ) / Σj exp(sim(q, dj) / τ) )

其中 τ 是温度系数（通常 0.01~0.1），控制分布锐利程度。

🔥 Hard Negative Mining（难负例挖掘）

随机负样本太简单，需要"难负例"来提升模型区分能力：

方法原理效果
同批次负采样Q1 的负样本包括 Q2、Q3 的正样本中等难度
BM25 负采样检索"看起来相关但实际不相关"的文档高难度，更逼真
跨批次负采样跨 batch 共享负样本增加干扰多样性

5. PyTorch 实现示例

Python - RAG Embedding 简化实现
import torch
import torch.nn as nn
import torch.nn.functional as F

# 句子向量生成：取 [CLS] token + 归一化
def encode_sentence(model, token_ids):
    output = model.encoder(token_ids)
    cls_vector = output[:, 0, :]  # [CLS] 向量
    cls_vector = cls_vector / cls_vector.norm(dim=-1, keepdim=True)
    return cls_vector

# InfoNCE 对比学习损失
def contrastive_loss(query_emb, pos_doc_emb, neg_doc_embs, temperature=0.1):
    pos_sim = torch.dot(query_emb, pos_doc_emb) / temperature
    neg_sims = torch.matmul(neg_doc_embs, query_emb) / temperature
    loss = -torch.log(torch.exp(pos_sim) / (torch.exp(pos_sim) + torch.exp(neg_sims).sum()))
    return loss

# 实际使用：Sentence Transformers
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')
doc_embeddings = model.encode(docs, normalize_embeddings=True)
query_embedding = model.encode(query, normalize_embeddings=True)

# 归一化后，余弦相似度 = 简单点积
similarity = query_embedding @ doc_embeddings.T

📐 余弦相似度 2D 可视化

在高维向量空间中，文档的相似度通过余弦相似度来衡量。相似度越高，两个向量越"接近"。

cosine_similarity(A, B) = (A · B) / (||A|| × ||B||)

🗄️ 向量数据库比较

不同的向量数据库采用不同的索引策略，适用于不同的场景：

数据库 索引类型 原理 适用场景
FAISS Flat IVF 暴力搜索或倒排索引 单机、轻量级场景
Chroma Flat HNSW 简单的持久化存储 + HNSW 图索引 嵌入式/轻量级应用
Milvus Flat IVF HNSW 分布式向量搜索引擎 大规模生产环境
索引类型解释
  • Flat：暴力搜索，遍历所有向量，速度慢但精确
  • IVF (Inverted File)：倒排索引，先聚类再搜索，加速但有精度损失
  • HNSW (Hierarchical NSW)：图索引，构建分层邻近图，高速高精度

💻 代码实现

PyTorch RAG 检索示例
import torch
from sentence_transformers import SentenceTransformer

# 1. 加载 Embedding 模型
model = SentenceTransformer('all-MiniLM-L6-v2')

# 2. 对文档进行编码
documents = ["文档1内容...", "文档2内容...", ...]
doc_embeddings = model.encode(documents)

# 3. 对查询进行编码
query = "用户的问题是什么？"
query_embedding = model.encode(query)

# 4. 计算余弦相似度
cos_sim = torch.nn.functional.cosine_similarity(
    torch.tensor(query_embedding).unsqueeze(0),
    torch.tensor(doc_embeddings)
)

# 5. 获取 Top-K 结果
top_k = 3
_, indices = torch.topk(cos_sim, top_k)
results = [documents[i] for i in indices]
