🤖 RAG 生成阶段 (Generate)

LLM 如何基于检索到的知识"写出"答案？

🎯 核心问题

检索已经拿到了"参考资料"，接下来 LLM 如何利用这些资料生成正确答案？

📚 类比：开卷考试

想象你参加一场开卷考试：

  • 纯记忆生成 = 考试前没复习，完全靠蒙（瞎编）
  • 带上下文生成 = 考试时可以翻书，根据书上的内容组织答案

RAG 的生成阶段就是"查书答题"的过程：模型不再是凭记忆编造，而是基于检索到的真实知识来组织答案。

🔑 核心区别

检索阶段找到"答案可能在哪些页"
生成阶段从这些页面中"提炼、整理、输出"正确答案

📊 RAG 评估指标

Recall@K
检索到的相关文档占所有相关文档的比例。K 是检索返回的文档数量。
MRR
Mean Reciprocal Rank，第一个相关文档排名的倒数平均值。
Hit Rate@K
前 K 个结果中包含相关文档的比例。
Faithfulness
答案与检索上下文的忠实度，衡量生成内容是否基于检索结果。

公式：
Recall = TP / (TP + FN)
Precision = TP / (TP + FP)
F1 = 2 × Precision × Recall / (Precision + Recall)

⚠️ RAG 何时失败

了解 RAG 系统的三大失败场景，帮助你更好地设计和优化系统：

💨 场景1：检索不到相关内容
问题：用户问题与知识库中任何文档的语义都不匹配。

表现：检索返回空结果或完全不相关的文档。

后果：LLM 无法基于上下文生成，只能靠"幻觉"回答。
✂️ 场景2：上下文超出长度限制
问题：检索返回的文档太多/太长，超过了 LLM 的上下文窗口。

表现：长文档被截断，早期内容被"遗忘"。

后果：答案不完整或关键信息丢失。
⚔️ 场景3：多文档信息冲突
问题：多个源文档对同一问题有不同的答案。

表现：LLM 在不同信息之间"纠结"。

后果：生成的回答自相矛盾或含糊其辞。

💻 RAG 生成代码示例

rag_generate.py
def rag_generate(query, retrieved_docs, llm_model, tokenizer):
    # 1. 组装增强 Prompt
    context = "\n".join(retrieved_docs)
    prompt = f"""基于以下参考信息回答问题：

参考信息：
{context}

问题：{query}
答案："""

    # 2. Tokenize
    inputs = tokenizer(prompt, return_tensors="pt")

    # 3. 逐 token 自回归生成
    outputs = llm_model.generate(
        inputs["input_ids"],
        max_new_tokens=256,
        do_sample=True,
        temperature=0.7
    )

    # 4. 解码
    response = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return response
