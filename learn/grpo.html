🎯 SFT、DPO、GRPO 三者对比

三者都是在预训练模型基础上微调，但学习方式和数据标签不同：

SFTDPOGRPO
本质 监督学习 偏好学习（离线） 偏好学习（在线）
数据标签 标准答案 偏好排序（哪个更好） Reward 评分
数据来源 人工标注 人类标注/AI 反馈 模型自己生成
训练阶段 SFT 之后 SFT 之后 SFT 之后
典型应用 基础能力 对齐人类偏好 数学/代码推理
💡 通俗类比

SFT = 老师出题，学生抄答案，背答案

DPO = 老师展示两份答案，学生判断哪个更好，反复练习好答案

GRPO = 学生自己写多份答案，自己批改认为最好的，反复练习最好的

🎯 为什么需要强化学习？

SFT 和 DPO 都依赖于人工标注的数据，有没有方法让模型自己生成训练数据？

💡 类比：训练小狗

小狗做对了 → 给零食奖励（正奖励）

小狗做错了 → 不给零食（无奖励或负奖励）

逐渐学会正确行为 —— 这就是强化学习的思想！

🧠 GRPO 核心思想

GRPO 让模型：

  1. 生成多个答案 —— 针对同一个问题，让模型生成 G 个不同的回答
  2. 用奖励模型打分 —— 每个答案都有一个"好坏"分数
  3. relative 相对比较 —— 不看绝对分数，只看 G 个答案中谁相对更好
  4. 强化好的，削弱差的 —— 奖励高的答案加强，奖励低的答案削弱

📊 什么是 "Group Relative"？

GRPO 的关键创新：不使用绝对分数，而是使用相对比较！

例如：生成 4 个答案，用奖励模型打分

答案 1
太短了
0.2
答案 2
一般般
0.5
答案 3
还不错
0.7
答案 4
最详细
0.9

传统方法： 把绝对分数 0.9, 0.7, 0.5, 0.2 作为 reward
GRPO 方法（组相对）： 只关注相对排名，用 softmax 把分数转换成概率分布

📐 梯度更新详解

GRPO 的梯度方向：提高高 Reward 答案的概率，降低低 Reward 答案的概率

梯度流向：

# 问题: "计算 1+1+2+3+4"
模型生成 → [G1="9", G2="10", G3="8"]
Reward 打分 → [R1=3, R2=10, R3=2]
                           ↑
                      G2 最高 = 正例
                           ↓
              Loss 低 → 模型认为自己产生 G2 的方式是对的
                           ↓
              提高生成 G2 类型答案的概率，降低 G1/G3 类型答案的概率
优势 (Advantage) 计算

GRPO 使用相对优势，而不是绝对分数：

# 绝对优势（传统方法）
advantage_i = R_i  # 直接用 reward，最高的总是赢

# 相对优势（GRPO 使用的）
advantage_best = R_best - mean(R_others)

# 优势归一化（减少方差）
advantage_normalized = (R_best - mean(R_all)) / std(R_all)

相对优势的好处：如果整体分数都偏高或偏低，奖励模型打分会波动。相对优势可以消除这种系统性偏差。

⚠️ KL 散度约束

GRPO 带 KL 约束，防止模型为迎合 Reward 而产生极端行为：

# GRPO 带 KL 惩罚的 Loss
L = -log σ(score_best - mean(scores_others)) + β × KL(π || π_old)

# β: KL 惩罚系数，通常 0.01~0.1
# π_old: 更新前的参考模型
# KL 项：保证新模型不会偏离旧模型太远

# GRPO 训练步骤

# 1. 对于每个问题，生成多个答案
for prompt in prompts:
    responses = model.generate(prompt, num_return_sequences=G)

    # 2. Reward 模型打分
    rewards = reward_model(prompt, responses)  # [G,]

    # 3. 相对比较：选最高分作为正例，其他作为负例
    best_idx = rewards.argmax()
    best_reward = rewards[best_idx]
    mean_reward = rewards.mean()

    # 4. 计算 GRPO Loss（带 KL 约束）
    advantage = best_reward - mean_reward
    loss = -log(sigmoid(advantage)) + β * KL_divergence

    # 5. 反向传播更新参数
    loss.backward()
    optimizer.step()

⚔️ GRPO vs PPO

PPO 是传统的强化学习算法，GRPO 是它的简化版本：

方面PPOGRPO
Value 网络 需要 不需要 ✓
reward 计算 需要 GAE 估计 直接使用原始分数
复杂度 高，4 个网络 低，只有策略网络
训练稳定性 一般 更稳定
代表性 PPO (Proximal Policy Optimization) DeepSeek-R1 同款
💡 为什么 GRPO 更好？

PPO 需要同时训练策略网络和 Value 网络（价值估计网络），两个网络需要协调配合，容易不稳定。

GRPO 只需要策略网络，通过 Group 内的相对比较来估计"好多少"，去掉了 Value 网络，大大简化！

🔍 为什么 Group Relative 能减少方差？

假设 reward 模型对不同问题打分的尺度不一样：

问题 A（数学题）

答案1: 0.1分，答案2: 0.2分

差距 = 0.1，但可能都偏低

问题 B（对话）

答案1: 5.0分，答案2: 5.1分

差距 = 0.1，但可能都偏高

如果用绝对分数训练：

  • 数学题 reward 普遍低，模型学会"这类题 reward 都低"
  • 对话 reward 普遍高，模型学会"对话不需要认真做"

如果用相对优势训练：

  • 每个问题内部比较，不受整体尺度影响
  • 模型学到的是"在这个具体问题上，什么更好"

🔢 批量梯度更新机制

所有方法（SFT/DPO/GRPO）都采用批量梯度下降：

# 三种方法都是这个模式
for batch in dataset:           # 每次取一批数据
    loss = compute_loss(batch)        # 计算损失
    loss.backward()                   # 反向传播
    optimizer.step()                  # 更新参数
💡 使用 LoRA 时的区别

默认更新全部参数；用 LoRA 时只更新 A、B 矩阵：

  • 全参数微调：W, A, B 全部更新
  • LoRA 微调：只有 A 和 B 矩阵更新，原始 W 冻结

📝 总结

GRPO = 生成多个答案 → 奖励打分 → 相对比较 → 强化好的

🎯 GRPO 关键点：

  • 核心思想：Group Relative，通过组内相对比较学习
  • 无需 Value 网络：比 PPO 更简单、更稳定
  • 自举式学习：可以自己生成数据，不需要人工标注
  • 梯度方向：提高高 Reward 答案概率，降低低 Reward 答案概率
  • 典型应用：DeepSeek-R1, OpenAI o1 等推理模型
